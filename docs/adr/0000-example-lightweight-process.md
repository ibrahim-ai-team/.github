## Context

This organization is establishing reusable AI-assisted engineering practices with a small maintenance budget. An overly formal architecture review process could cost more time than it saves.

## Decision

**Illustrative proposal only:** use a short Markdown ADR for consequential cross-repository decisions, and avoid ADRs for routine, easily reversible implementation choices. This example is not an accepted organization-wide technical decision.

## Alternatives considered

- **No written decisions:** lowest immediate effort, but context can be lost between sessions and contributors.
- **Heavyweight architecture documents for every change:** thorough, but disproportionate for a small evolving project.
- **Short ADRs for consequential choices:** preserves rationale with limited overhead.

## Consequences

The lightweight approach aims to preserve important context without requiring a separate tool or paid service. Maintainers should revisit the process if records become stale or decisions cannot be traced to implementation.
